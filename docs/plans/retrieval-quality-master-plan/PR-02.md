# PR-02 — Candidate tracing and benchmark observability

**Declared before corpus measurement:** 2026-07-14

**Evidence class:** deterministic correctness plus performance/operations

## Hypothesis

An opt-in trace can account for every candidate from source retrieval through
filtering, fusion, deduplication, project-level merging, rerank-pool selection,
and final output without changing Tessera's default ranking. The trace should
make candidate recall and duplicate crowding measurable before PR-03 changes
the candidate budget.

This PR does not add a candidate source, change a score, expand a pool, or
change a default. Any quality delta is a failure of the observational
invariant, not an improvement.

## Predeclared gates

1. Traced and untraced results are exactly equal on deterministic keyword,
   semantic, source-filter, file-deduplication, shortcut, and graph fixtures.
2. The untraced six-repository development run has the same per-query rank and
   ordered top-file list as the frozen PR-01 baseline.
3. Every retrieved candidate in deterministic fixtures has source-channel
   attribution and either a final rank or an explicit exclusion reason.
4. With tracing enabled, added warm-search p95 is at most 25 ms and relative
   p95 is at most 1.5x on the development corpus. A serialized per-query trace
   is at most 250 KiB at the current benchmark limit.
5. Tracing remains off by default. Normal MCP result payloads contain no trace;
   server traces are emitted only under explicit debug logging.
6. Relevant unit/integration suites and lint pass. No holdout data is opened.

The performance budget applies to the deliberately verbose diagnostic mode,
not normal search. The disabled path is limited to optional-collector branch
checks and is covered by the unchanged corpus-output invariant.

## Measurements

The development benchmark reports, for keyword, semantic, graph, and fused
union candidates:

- Recall@10, @20, and @50;
- candidate and unique-file counts;
- duplicate-file rate and file diversity;
- complete-attribution status;
- exact query/repository/model/revision metadata inherited from PR-01.

Federated traces additionally record the project-local source, global rank,
raw score distribution, project concentration, pairwise score-range overlap,
rerank-pool inclusion, reranker input/output rank, and final project sequence.
Raw RRF/reranker values are explicitly not represented as probabilities.

## Reproduction commands

```bash
uv run pytest -q tests/unit/test_search_trace.py tests/unit/test_search.py
uv run python scripts/benchmark_development.py \
  --tier quick --trace --output benchmarks/development-candidate-trace-2026-07-14.json
```

The before/after comparison uses
`benchmarks/development-baseline-2026-07-14.json` as the frozen untraced
baseline and compares every query's rank and ordered `top_files` list.

## Result

Passed at `a73c373ec93246b1fd22b57df0b0ab6799a8e0e0` on all six
development repositories and 30 queries. All 300 paired traced/untraced calls
were exactly equal, as were all frozen-baseline ranks and ordered top-file
lists. Tracing added 0.8976 ms at p95 (1.1806x), and the largest trace was
48,898 bytes. Complete attribution held for every query.

See [the candidate tracing benchmark report](../../benchmark-candidate-tracing-2026-07-14.md)
and its linked machine-readable artifacts. The diagnostic result supports the
existing PR-03/04/05 hypotheses; it does not change a score or select a
production constant.
